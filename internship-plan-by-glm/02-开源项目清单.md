## 参与开源 vs 二次开发：真实门槛与回报

**提 PR 到成熟大项目**：门槛 = 从 issue 淹没区找到能做的 + CLA/代码规范/测试要求，从领 issue 到合并 1-4 周；回报 = "Contributor to XXX" 的可信度远高于自述，且能看到资深维护者如何 review——这是最值钱的部分。
**二次开发**：门槛低，但风险是"套壳 CRUD"一眼被看穿；回报 = 可控地展示自己的架构决策（上下文工程、记忆管理），是面试深挖的弹药库。关键是把自研引擎锚定在可对比的参照物上（pi 就是最好的对照系）。

**结论：不是二选一，而是组合**——二开项目做主菜（架构能力），顺手把二开中真实撞到的 bug 回报给所用框架（langchain4j / agents-flex / a2a-java）做副业（社区协作能力）。刻意刷与主业无关的 PR 时间性价比低。

## 专项核实："llmwiki" 与 DeepWiki 平替

- **llmwiki 存在**：[lucasastorian/llmwiki](https://github.com/lucasastorian/llmwiki)（1,664 star，2026-10-02 活跃）——Karpathy 提出的"让 LLM 自己维护 wiki"概念的开源实现：上传文档、通过 MCP 接入 Claude 由它撰写维护 wiki。与你的方向（agent + 上下文工程 + 知识库）高度相关。另有 OpenLLMAI/OpenLLMWiki（270 star）已停更两年，是另一个同名不同物。
- **DeepWiki 开源平替**：[AsyncFuncAI/deepwiki-open](https://github.com/AsyncFuncAI/deepwiki-open)（18,124 star，唯一够格写进简历对标的平替）、AIDotNet/OpenDeepWiki（3,615，国产 C#，活跃）、sopaco/deepwiki-rs（3,107，Rust）。未发现名为 "Ascendara" 的平替（那是个游戏下载管理器）。

## Top 3 行动建议

1. **精读 + 对照**：`openai/openai-agents-python` 对照你已精读的 pi，把对比表写进自研引擎 README——这是上下文工程岗位最硬的证明。
2. **二开**：`langchain4j` + `pgvector` + `ruoyi-ai`（业务壳参考）做 Java 后端 + agent 业务项目；ragflow 的 DeepDoc 分块思路作检索质量加分模块。
3. **提 PR**：主攻 `a2a-java`（第一个 PR）→ `langchain4j`（与主线同构）→ backup `agents-flex`。
